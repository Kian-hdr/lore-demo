# Research foundations

L.O.R.E. studies a path from English intent through a typed outline, refinement and interface checks, predicted instructions, deterministic Wasm encoding, and an execution receipt. These eight sources help explain the design choices. The connections to L.O.R.E. below are design inferences. Its completed pilot uses one hand-authored graph and instruction fixture.

This is a focused comparison of selected precedents, checked in November 2026. It covers staged decoding, learned abstractions, compiler decisions, instruction search, and verification. A systematic novelty assessment and reproduction of these studies remain future work.

## Eight relevant precedents

**Next-Concept Modeling: Fast, Parallel Coarse-to-Fine Text Generation — Kumbong and colleagues, 2026.** A learned multiscale discrete representation supports generation from coarse codes toward a detailed text reconstruction. The transformer predicts the codes within each level in parallel. L.O.R.E.'s proposed typed program graph is a different representation whose semantics and execution checks must be specified separately. The [concept hierarchy guide](Concept_Hierarchy.md) makes this distinction visual. [Author preprint](https://arxiv.org/abs/2610.14162)

**Coarse-to-Fine Decoding for Neural Semantic Parsing — Dong and Lapata, ACL 2018.** The model first predicts a sketch with some details removed, then fills those details using both the input and sketch. This is a concrete precedent for generating an outline before its arguments. Its semantic-parsing tasks support investigating staged structure prediction. Whether a typed executable outline improves L.O.R.E.'s verified success or total latency needs a matched experiment. [Paper and metadata](https://aclanthology.org/P18-1068/)

**DreamCoder: Bootstrapping Inductive Program Synthesis with Wake-Sleep Library Learning — Ellis and colleagues, PLDI 2021.** DreamCoder learns a library of program components and a neural policy for searching over them, using synthesis tasks specified by examples. The library and search policy improve through an iterative learning process. This motivates comparing the effects of representation, learned search, and abstraction reuse separately. L.O.R.E.'s proposed fresh instruction generation addresses a different interface and evaluation setting. [Conference abstract](https://pldi21.sigplan.org/details/pldi-2021-papers/55/DreamCoder-Bootstrapping-Inductive-Program-Synthesis-with-Wake-Sleep-Library-Learnin)

**PICARD: Parsing Incrementally for Constrained Auto-Regressive Decoding from Language Models — Scholak, Schucher, and Bahdanau, EMNLP 2021.** PICARD rejects inadmissible token continuations through incremental parsing during decoding. The paper evaluates text-to-SQL generation. For L.O.R.E., this motivates checking permitted expansions before accepting a branch. A parser's acceptance addresses its formal constraints. Correspondence to the caller's intended behavior still needs separate evidence. [Paper and metadata](https://aclanthology.org/2021.emnlp-main.779/)

**MLGO: a Machine Learning Guided Compiler Optimizations Framework — Trofin and colleagues, 2021.** MLGO embeds learned decision policies in LLVM, with inlining for code size as its reported case study. It provides a precedent for giving a model a bounded compiler decision while retaining a conventional compiler around it. L.O.R.E. can similarly define exactly which choices a learned instruction head controls and which checks and encoding rules remain deterministic. The tasks and objectives differ. [Author preprint](https://arxiv.org/abs/2101.04808)

**Faster sorting algorithms discovered using deep reinforcement learning — Mankowitz and colleagues, Nature 2023.** AlphaDev searches over assembly instructions and evaluates candidate algorithms for correctness and performance in a restricted setting. This makes instruction-level search and execution feedback relevant comparisons. Its sorting results leave open the effectiveness of English-conditioned instruction prediction for other program families. The author explanation describes this search and its assembly-level environment. [Paper](https://www.nature.com/articles/s41586-023-06004-9), [author explanation](https://deepmind.google/blog/alphadev-discovers-faster-sorting-algorithms/)

**Alive2: Bounded Translation Validation for LLVM — Lopes and colleagues, PLDI 2021.** Alive2 uses an SMT solver to check refinement between LLVM IR functions. It bounds resources, including loop expansion, and describes circumstances in which bugs can be missed. It motivates specifying the semantics and coverage of each representation-to-representation check. L.O.R.E.'s pilot currently validates Wasm and executes finite tests. Adding a semantic translation checker would be a separate implementation. [Author manuscript](https://web.ist.utl.pt/nuno.lopes/pubs/alive2-pldi21.pdf)

**Is Your Code Generated by ChatGPT Really Correct? Rigorous Evaluation of Large Language Models for Code Generation — Liu and colleagues, 2023.** EvalPlus expands tests using generated inputs and type-aware mutation, then evaluates programs against a reference implementation. Its experiments expose incorrect programs that passed the original tests. This motivates an oracle maintained independently of the generation path, broader boundary cases, and locked evaluation families. A passing finite suite gives evidence for its tested cases. [Author preprint](https://arxiv.org/abs/2305.01210)

## Design decisions to test

These comparisons motivate experiments. The proposed controls below are L.O.R.E. study choices.

| Decision | Relevant precedent | Proposed comparison |
| --- | --- | --- |
| Predict an outline before details | Dong and Lapata | Compare hierarchical and flat prediction using the same grammar, model budget, target, and checks. |
| Introduce reusable abstractions | DreamCoder | Measure reuse separately from fresh component generation. |
| Check branches during generation | PICARD | Compare early constraints with final-only checks, counting rejected work and retries. |
| Learn instruction choices | MLGO, AlphaDev | Retain the fixed lowerer as a control. Compare predicted instructions with and without bounded execution-state feedback. |
| Establish correctness | Alive2, EvalPlus | Report interface validity, tested behavior, and any future semantic validation as distinct outcomes. |

For performance, record the whole path to a verified artifact, including failed attempts, checks, and repairs. The one-kernel pilot supplies an encoder-and-runner control. Generalization, learned planning, automated repair, and comparative improvements require their own data and experiments.
